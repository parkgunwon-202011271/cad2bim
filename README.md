# cad2bim

건축 CAD 평면(DWG 폴더)을 층이 나뉜 3D 모델(SketchUp, IFC)로 바꿉니다. 비공개 저장소입니다.

설계와 규칙은 [상세설계.md](상세설계.md), 시험 데이터는 [data/public/README.md](data/public/README.md)를 보세요.

현재 확인한 기능과 미검증 항목은 [기능 체크리스트](docs/CHECKLIST.md), 다음 작업과 완료 기준은 [TODO](docs/TODO.md)를 보세요.

## 다른 컴퓨터에서 설치

Windows 11과 Python 3.11 이상만 있으면 됩니다. 패키지 버전은 `requirements.txt`에 고정되어 있고, DWG를 읽는 LibreDWG는 `third_party/libredwg`에 함께 들어 있습니다.

```powershell
git clone git@github.com:parkgunwon-202011271/cad2bim.git
cd cad2bim
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python scripts\verify.py     # 주민센터를 변환해 기준값과 비교. 마지막 줄이 "재현 성공"이면 끝
python -m app                # 앱 실행
```

| 항목 | 저장소에 있나 | 없으면 |
|---|---|---|
| Python 패키지 | `requirements.txt`로 설치 | 실행 불가 |
| LibreDWG 0.14.8829 | 있음 (`third_party/libredwg`) | — |
| SketchUp C SDK | 없음 (재배포 금지, 선택 설치 1번) | skp만 빠지고 나머지는 출력 |
| 렌더링 패키지 | 없음 (선택 설치 2번) | 조감도만 건너뜀 |
| 실사화 환경 | 없음 (선택 설치 3번) | 실사화만 건너뜀 |

조감도와 실사화는 지금 꺼져 있습니다(`aerial_enabled`, `photo_enabled`). 앞 단계 품질을 먼저 올리기로 했기 때문입니다.

테스트: `cd core` 후 `python -m pytest -q`. SDK가 없으면 skp 테스트는 건너뜁니다. 지금 `test_slab_covers_the_floor_below_the_level` 1건이 부동소수점 비교(-199.99999999999972 ≠ -200.0)로 실패합니다. 앱과는 무관합니다.

ODA File Converter는 비회원이면 비상업 용도만 허용되므로 쓰지 않습니다.

## 시연 재현 (주민센터, 규칙 기반)

시연은 공개 도면 주민센터(`data/public/주민센터`)를 규칙만으로 변환해 보여 줍니다. 외부로 아무것도 보내지 않고, 같은 도면이면 같은 결과가 나옵니다.

```powershell
git pull
.venv\Scripts\activate
pip install -r requirements.txt
python scripts\verify.py              # 마지막 줄 "재현 성공" 확인 (벽 101, 기둥 61, 문 37, 창 34, 실 38, 3D 해시 3bf27045e0f4a14e)
python -m app data\public\주민센터    # 앱을 열면서 주민센터 결과를 바로 보여 줌
```

- 앱에서 직접 변환하려면 '도면 폴더 열기'로 `data\public\주민센터`를 고릅니다. 20초 안팎(처음 한 번은 DWG 변환으로 1분쯤)입니다.
- LLM은 꺼져 있습니다. `.env`에 API 키가 있어도 `CAD2BIM_LLM`을 비워 두면 규칙 기반입니다(아래 'LLM 켜기').
- 층 구성: `주민자치센터_1층평면도_B안(최종).dwg` 한 파일에 1·2·3층이 다 들어 있고, 따로 있는 `2층`·`3층 평면도` 파일은 다른 버전입니다. 모든 층을 한 벌로 담은 파일이 하나 있으면 그 벌을 씁니다(버전이 섞이면 3층이 어긋납니다).
- 확인할 화면: 3층은 L자로 작고 2층 옥상 테라스와 맞물립니다. 3D/2D/분할 탭, 층 목록, 사람 시점(W·A·S·D).
- 내장 샘플(`app/web/sample`, 앱의 '샘플 보기')도 같은 결과로 만들어 두었습니다. 다시 만들 때는 `python -m app.sample`.

## 앱 (프로토타입)

`python -m app`으로 창이 열립니다. DWG 폴더나 DWG·DXF 파일 여러 개를 창에 끌어다 놓으면 변환하고, 3D 모델을 360도로 돌려 볼 수 있습니다. 끌어다 놓기가 안 되면 "도면 폴더 열기"를 씁니다.

- 원칙: 도면을 그대로 옮긴다. 층 도면끼리 맞지 않는 곳(예: 1층 B안의 계단·벽이 2층 보이드와 어긋남)은 고치지 않고 그대로 둔다.
- 3D: W·A·S·D 이동, Q·E 아래·위, Shift 빠르게. 마우스는 드래그 회전, 휠 확대(커서 쪽으로), 오른쪽 드래그 옮기기. 층·지붕·대지 표시를 켜고 끕니다.
- 화각: 밖에서는 40°, 바닥에서 3m 안으로 내려오면 70°로 넓어집니다.
- 사람 시점("보기"의 버튼): 보던 자리의 바닥에 눈높이 1.6m로 섭니다. W·A·S·D 걷기, Shift 뛰기, 드래그로 둘러보기, 휠로 시야 조절, Esc로 나가기. 벽·창·난간은 막고 문은 지나가며, 0.45m 이하 턱과 계단은 오릅니다. 내부 보기(단면)는 잠시 꺼져 천장까지 보이고, 나오면 들어가기 전 시점으로 돌아갑니다.
- 가구: 도면의 가구·위생기구 레이어(FURNITURE)에서 가구 하나하나를 찾아 종류별 입체로 세웁니다("표시"에서 끄고 켬). 닫힌 도형뿐 아니라 낱개 선으로 그린 가구도 선이 둘러싼 면으로 찾습니다. 종류는 ① 이름표(가구 안이나 곁의 글자, 가구를 가리키는 지시선 글자. `config/defaults.yaml`의 `furniture_labels`) ② 기호(X 표시=키 큰 장, 빗금=유리 진열장, 버너 원=가스레인지, 둥근 볼=개수대, 등받이 띠=의자·소파) ③ 크기 순서로 정하고, 이름표가 붙은 가구와 같은 모양의 가구는 같은 종류로 봅니다. 의자는 다리·좌판·등받이, 탁자는 상판·다리, 조리대는 받침·몸통·상판처럼 부재를 나눠 만들며 바닥 모양은 도면 그대로이고 높이는 추정입니다. build가 `furniture.json`으로 내보내며 모델 파일(DAE·IFC·SKP)에는 넣지 않습니다.
- 엘리베이터: 승강로 표시와 'EV'·'엘리베이터' 글자로 찾습니다. 위아래 층이 같은 자리면 바닥을 뚫어 승강로로 잇고(모델 파일에도 반영), 앱에서는 카와 승강장 문을 만듭니다. 사람 시점에서 문 앞에 서면 카가 오고, 카 안에서 숫자키(층 번호)나 PageUp/PageDown으로 층을 고릅니다. 층마다 자리가 다르면 잇지 않습니다.
- 보기 스타일: "건축"(기본, Revit의 음영+모서리처럼 재료색과 모서리 선)과 "분류 색"(기둥 파랑·문 초록 등 인식 확인용). 모델 파일 색은 바꾸지 않습니다.
- 내부 보기: 층을 고르면 그 층만 남기고 바닥 1.25m 높이에서 잘라 위에서 봅니다(난간 1.2m와 겹치지 않게). 잘린 면은 진하게 칠합니다.
- 2D: 입력 도면을 그림으로 봅니다. 숫자만 8자리 이상인 글자(학번 등)는 그리지 않습니다.
- 폴더를 놓으면 결과는 그 폴더의 `_cad2bim_out`에, 파일을 놓으면 `%LOCALAPPDATA%\cad2bim\jobs\`에 생깁니다.
- 기본은 외부 통신이 없습니다. `CAD2BIM_LLM=anthropic`을 켜면 레이어 이름과 통계(좌표·글자 내용 제외)를 Claude로 보냅니다(아래 "처리 단계와 LLM 도입 계획"). three.js 0.170.0(MIT)도 `app/web/vendor`에 들어 있습니다.

## 선택 설치

### 1. SketchUp C SDK

Trimble 개발자 사이트에서 약관에 동의하고 받아 `C:\SDK_Win`에 풉니다. 다른 위치라면 환경 변수 `CAD2BIM_SKETCHUP_SDK`에 지정합니다.

- SDK는 재배포가 금지되어 있어 저장소에 넣지 않습니다.
- Trimble의 서면 승인 전에는 skp 출력을 외부 고객에게 제공하지 않습니다.

### 2. 조감도 그림

```powershell
pip install -e ".[render]"
```

`config/defaults.yaml`에서 `aerial_enabled`를 `true`로 바꿉니다.

### 3. 실사화

NVIDIA 그래픽 카드(메모리 16GB에서 확인)와 저장 공간 약 12GB가 필요합니다. 모든 계산은 PC 안에서 끝나고 실행 중 인터넷을 쓰지 않습니다.

**기본 환경에 `diffusers`를 설치하지 마세요.** `huggingface_hub`가 함께 올라가 `transformers`를 쓰는 다른 프로그램이 깨집니다. 반드시 별도 가상환경에 설치합니다.

```powershell
python -m venv --system-site-packages $HOME\.cad2bim_ai
& $HOME\.cad2bim_ai\Scripts\python.exe -m pip install "diffusers==0.42.1" transformers accelerate safetensors
```

CUDA를 쓰는 PyTorch가 기본 환경에 있어야 합니다. 이어서 같은 파이썬으로 아래 모델을 내려받습니다.

| 모델 | 라이선스 |
|---|---|
| `SG161222/RealVisXL_V4.0` | OpenRAIL++ |
| `madebyollin/sdxl-vae-fp16-fix` | MIT |
| `diffusers/controlnet-depth-sdxl-1.0` | OpenRAIL++ |
| `diffusers/controlnet-canny-sdxl-1.0` | OpenRAIL++ |

다 받으면 `config/defaults.yaml`에서 `photo_enabled`를 `true`로 바꿉니다.

## 실행

입력 폴더는 `data/` 안이거나 프로젝트 밖이어야 합니다. 프로젝트의 다른 곳은 막아 두었습니다. `data/`에는 공개 도면과 AI 인식이 승인된 도면만 둡니다.

```powershell
cd core
python -m cad2bim.cli build ..\data\public\주민센터 --jobs 3
python -m cad2bim.cli compare-model ..\data\public\주민센터 "..\data\public\주민센터\주민센터 모델링.skp" --floor-height 4500
```

결과는 입력 폴더의 `_cad2bim_out`에 생깁니다. 현업에 전달할 파일은 `building_editable.skp`입니다. 설치가 맞다면 마지막 줄의 F1이 약 0.826으로 나옵니다.

실 면적은 `rooms.csv`에 두 기준으로 나옵니다: 안목(벽 안쪽)과 벽 중심선 기준. 도면의 면적 표기는 대개 중심선 기준이라 안목 면적은 표기보다 10~20% 작습니다. 도면에 면적이 적힌 실은 중심선 면적과의 차이도 적습니다(주민센터 32실: 차이 중앙값 3.3%, 5% 안 24실). IFC의 `IfcSpace`에는 `Qto_SpaceBaseQuantities.NetFloorArea`(안목)와 `Cad2Bim_SpaceAreas.CenterlineFloorArea`(중심선)로 들어갑니다.

## 처리 단계와 LLM 도입 계획

기본은 모든 단계가 규칙입니다. 아래는 LLM을 붙일 자리와 2026-11-19에 잰 정확도입니다. 아래 표의 측정은 Claude Opus 5.5가 대화 안에서 그림·텍스트만 보고 답한 뒤 정답과 맞춰 본 것입니다(1회, API·자동화 없음). API로 부르는 LLM은 'LLM 켜기'를 보세요.

### LLM 켜기 (선택)

`.env.example`을 `.env`로 복사해 키를 넣고 `CAD2BIM_LLM`을 정합니다(`openai`, `gemini`, `anthropic`, `cache`, `off`). `.env`는 커밋하지 않습니다. 비워 두면 규칙 기반입니다. 공급자는 `core/src/cad2bim/llm_client.py` 한 곳에서 부르고, 받은 답은 `_cad2bim_out/_llm/`에 쌓아 같은 도면이면 다시 묻지 않습니다. 하루 한도에 걸리면 거기서 멈추고 남은 곳은 대기 목록(`pending.json`)에 둡니다.

| 모델 (2026-11-19, 주민센터 24곳, 기준은 Claude 판단) | 그림+기준 | +도면 근거 2판 | 반영된 답의 정확도 (거르기 후) | 비고 |
|---|---|---|---|---|
| GPT-5.5 | 18 | 22 | 91% (23/24 반영) | 물류 1회 약 5~8달러(추정) |
| Gemini 3.5 Flash Lite (무료 등급) | 13 | 18 | 89% (19/24 반영) | 하루 500번, 보낸 내용이 Google 제품 개선에 쓰일 수 있음 |
| Qwen3-VL 8B (로컬, llama.cpp) | 13 | 15 | 88% (16/24 반영) | 레이어 판단은 계단 레이어를 바꿔 쓸 수 없음 |
| GPT-5.4 mini | 14 | 13 | — | 물류에서 콘크리트·외벽 패널 레이어를 지워 규칙보다 나빴음 |

도면 근거 = 상자와 겹치는 선의 레이어 역할별 개수, 상자 양쪽 실 이름, 둘레 4m 글자(계산이라 정확). 거르기 = 근거와 정면으로 어긋난 답(문 선이 있는데 열림, 모서리 기둥인데 문 등)과 도형 종류와 어긋난 레이어 역할(선만 있는 레이어를 글자로)은 적용하지 않음. 약한 모델이 사전이 맞힌 벽 레이어를 '기타'로 내리는 것은 아직 막지 않습니다(다음 작업).

| 단계 | 하는 일 | 담당 | 규칙 정확도 | LLM 정확도 | 측정 조건 |
|---|---|---|---|---|---|
| 1. 폴더 받기 | DWG→DXF, 단위·외부참조 확인 | 규칙 | 28/36 (78%) | — | 물류. 실패 8장 = 단위 7, 외부참조 누락 1 |
| 2. 분류 | 시트 종류, 한 장 안의 칸 나누기, 칸별 층 | **LLM** | 시트 11/36 (31%), 평면 층 6/7 | 시트 36/36, 평면 층 7/7, cc0/dev 칸 23/23 | 물류 36장 블라인드(파일명 숨김) + cc0/dev |
| 3-a. 레이어 역할 | 어느 레이어가 벽·기둥·문인지 | **LLM** | 35/40 (도면 평균 79%, 레이어가 숫자뿐인 A2는 1/6) | 46/46 (100%) | 합성 4장, 레이어 이름·도형 수·예시 글자만 줌 |
| 3-b. 선 분리 | 평행선 두 개가 벽인지 | 규칙 (애매하면 LLM) | 20/20 | 20/20 | 합성 A2(전부 레이어 0)에서 뽑은 선 쌍 20개 |
| 4-a. 수치 계산 | 좌표, 두께, 문 위치 | 규칙 | 도형에서 바로 계산 (합성 오차 중앙값 0mm) | 그림에서 읽으면 중앙값 12mm(합성, 1px=21mm), 70mm·최대 142mm(물류 2층, 1px=45mm), 기둥 22/24 | **LLM이 좌표를 만들면 안 되는 근거** |
| 4-b. 적힌 수치 읽기 | 단면도 층 레벨(FH), 창호표 | **LLM** + 규칙 대조 | 읽지 않음 → 층고 기본값 3,000mm | 층 레벨 6/6 | 물류 단면·입면. 정답은 레벨 기호의 속성값(16곳에서 일치) |
| 5. 조립 | 층 배치, 높이, 슬래브·계단 | 규칙 (+ LLM이 정한 층·높이) | 평면 5/7 사용, 층 높이 1/5 맞음(기준층만) | 7/7 배치 판단, 높이는 4-b 값 | 물류. "4층 상부"·지붕층은 규칙이 버림 |
| 6. 검증 | 결과를 도면에 겹쳐 빠진 벽·엉뚱한 문 찾기 | **LLM** + 규칙 | 없음 | 숨긴 오류 8/8, 잘못 짚음 0 | 합성 2장에 벽 삭제·문 삭제·가짜 벽·기둥 이동을 무작위로 넣음 |
| 7. 출력 | DAE, IFC, DXF, SKP | 규칙 | IFC 스키마 오류 0, 부피 불일치 0/572, SKP 905/906 | — | 물류 |
| 8. 사용자 보기 | 확인·수정(수정은 나중에 학습 데이터) | 사람 | — | — | — |

지킬 것:

- LLM은 이름표를 붙이고 고르기만 합니다(벽 레이어다, 이 칸은 2층이다, 층고는 4,250이다). 좌표는 만들지 않습니다(4-a).
- LLM이 읽은 수치는 도면에 그 글자가 실제로 있을 때만 씁니다. 판단이 형상과 맞지 않으면(벽 레이어라는데 평행선이 없음) 버리고 규칙 결과를 쓰거나 사용자에게 묻습니다.
- LLM 응답은 저장해 다시 써서 같은 도면이면 같은 결과가 나오게 합니다. LLM이 실패하면 규칙으로 돌아갑니다.
- 도면을 외부 AI에 보내는 것은 켜고 끄는 선택 기능으로 둡니다. 꺼 두면 지금처럼 외부 통신이 없습니다.

한계: 합성 도면은 4장이고 규칙도 이 도면으로 만들었습니다. 실제 도면의 벽·문 정확도는 정답이 없어 아직 잰 적이 없습니다. 측정한 모델은 Opus 5.5 하나이고, 값싼 모델(Sonnet, Gemini Flash)은 재지 않았습니다. 물류 단계는 측정 전에 같은 대화에서 도면을 본 적이 있습니다.

측정에 쓴 그림은 `out/llm_실험_그림/`에 있습니다(물류 도면이 들어 있어 커밋하지 않음): 시트 분류 36장 비교, 평행선 20쌍, 좌표 읽기(물류 2층·합성), 숨긴 오류 찾기 2장, 블라인드용 시트 원본 렌더.

한 줄로: 좌표 계산과 파일 만들기는 규칙, "무엇인지 판단·적힌 것 읽기·결과 검사"는 LLM. LLM이 실패하면 규칙 결과를 씁니다.

앱의 층 이름: `R`은 "지붕층", `F4M`은 "4층 상부"로 보입니다. 주민센터 재현값과 합성 벤치마크는 그대로입니다(LLM 꺼짐).

### 규칙을 LLM의 도구로 쓰기

평소에는 규칙 파이프라인만 돌고(빠르고, 공짜이고, 같은 도면이면 같은 결과), 검증에서 문제가 나오거나 규칙이 "모름·실패"를 낼 때만 LLM이 규칙을 도구로 불러 원인을 보고 다시 돌립니다. LLM이 정한 것은 설정 파일(레이어 역할 `layer_map.json`, 시트 분류 `map.json`, 층 높이)로 남겨, 다음부터는 LLM 없이 같은 결과가 나옵니다.

| 주는 도구 | 주지 않는 도구 |
|---|---|
| 레이어 목록 보기·역할 정하기 | 벽·기둥을 좌표로 추가·이동 |
| 시트 그림 보기·칸 나누기·층 이름 붙이기 | 도면 선 지우기 |
| 위치 근처 글자 읽기(레벨, 실 이름) | 정해진 범위 밖의 설정값 |
| 구역만 인식 다시 돌리기(범위 안 설정) | |
| 결과를 도면에 겹쳐 보기, 층끼리 비교 | |
| "도면 문제"로 보고하기 | |

오른쪽을 막아야 "도면을 그대로 옮긴다"가 지켜집니다. 도구 호출 횟수에 상한을 두고, 모든 호출을 기록해 앱에서 "LLM이 바꾼 것"으로 보여 줍니다.

## 지켜야 할 것

- 물류 도면과 출처·라이선스가 불분명한 외부 도면은 저장소에 올리지 않습니다. 로컬 `data/` 아래(`data/물류_B동/`, `data/public/외부도면/`)에 두면 `.gitignore`가 막습니다.

- `.gitignore`는 합성 도면과 `data/public/`(외부도면 제외)만 예외로 허용합니다. 다른 곳의 도면은 커밋되지 않습니다.
- 시험용 도면은 결과를 보고 규칙을 고치는 데 쓰지 않습니다.
